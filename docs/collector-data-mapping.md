# 1688采集映射 v2.1

## 使用方式

1. 更新本机服务后，在Edge/Chrome扩展管理页对 `extension` 目录中的品探采集助手点击“重新加载”。版本为2.1.0，已有配对无需重建。
2. 在工作台输入详情链接并采集。扩展分区读取标题、价格、SKU、属性、包装、供应商、评价和详情。
3. 在“标准商品资料与数据缺口”核对字段、单位、原文和冲突。未能识别的区域留空；受登录/验证码限制时仍等待人工处理。
4. 在人工复核草稿中取消字段、修改值或补录字段；图片可修改主图/SKU图/详情图分类，也可排除。删除是复核排除，原始页面证据不会物理删除。
5. 人工确认后，保留的内容字段和图片分类才发布给后续流程。必须有真实商品标题；旧母版及其证据继续保留。

## 数据库结构与边界

- `collection_runs`：原始快照、采集时间、商品链接；新增 `text_blocks` 保存原文区域与选择器。旧版 `visible_text` 保持兼容。
- `offer_snapshots`：按采集批次保存标准化货源资料、数值转换、映射版本、下游缺口。
- `offer_mapping_history`：映射规则更新前的结果存档；重新处理保留原始快照和历史映射版本。
- `fact_evidence`、`offer_fields`：页面原文及每个字段的证据外键。PE/HDPE等冲突保存多个候选值，字段不自动二选一。
- `offer_price_tiers`：明确数量条件、计价单位和单价；当前只解析同一行明确呈现的阶梯。价格范围不是价格阶梯，SKU适用范围保持待复核。
- `collected_skus`：页面选项原文、证据ID、明确单价/库存与图片来源；单个选择项不冒充多维SKU完整组合。范围价、万+库存保持空值。
- `supplier_snapshots`：供应商原始指标和证据。页面等级不冒充官方质量分。
- `pain_points`：评价原文候选；尚未完成的痛点归纳不作为确定痛点，缺少样本分母时不计算频次。
- `asset_requirements`：内容所需素材，与真实 `product_assets` 分开。同类可上传多张，已有素材关联需求。
- `product_claims`：人工确认后的内容字段，引用 evidence_id；旧证据继续保留。已有母版、评分与CSV兼容数据不删除。

## 必需与可选映射

- 商品身份必需：offer ID、标题、链接、采集批次；标题不使用公司名代替。
- 稳定评分需要类目、功能标签、明确近30天销量、复购率；采购单价、单位、目的地运费、参考售价及供应商质量代理分需另行确定。缺失为null，不转换为0，也不生成排名。
- 爆款匹配需要同规格/SKU、材质或功能、包装数、供应商证据。市场零售价、趋势增速及目标痛点由需求侧提供，1688供应页不能补出这些市场信号。
- 内容需要标题及可引用规格、功能、使用条件和素材证据。参数取决于类目：日用品不要求电池容量、功率。
- 可选增强：颜色、定制、物流时效、评价摘要、使用场景。价格、销量、供应商宣传和评价不会因点击确认自动成为功效文案。
- 图片OCR仍是独立待复核线索，不能自动升级为规格事实。图片使用授权保持原流程。

字段白名单和理由唯一维护在 `src/pintan/collector_mapping.py` 的 CATALOG 中，工作台直接展示此目录。

## 迁移与验收

`python scripts/migrate_collector_mapping.py` 用SQLite备份API保存备份，再执行schema v5加表和幂等历史快照回填。不会重新下载图片或调用模型。备份位于 `data/backups`。

新映射是下游数据准备层。当前评分公式与模型保持原实现，缺少采购情境的商品不会自动写入稳定评分池或爆款搜索候选。后续选品接入应以准备情况和所选SKU为门槛，不能用页面最低价直接填充批发单价。

离线验证使用临时SQLite和DOM替身。真实1688页面布局可能不同；旧版扩展回传只能标记为历史整页快照，不视为新版分区采集验收。
