# 原图分类与图片规划

采集完成或上传原图后，系统对所有未排除、已下载素材执行 OCR，再调用
qwen3.7-plus 进行视觉分类。宽高均不超过160像素的素材直接过滤，保留来源和文件。
采集页的“分类全部原图 / 重试失败项”可补处理历史商品；成功结果按文件哈希、商品、
来源元数据、模型和版本缓存。单张失败不阻塞其他图片，OCR失败不会冒充识别成功。

`asset_analyses` 保存原图主分类、多标签、置信度、理由、风险与待复核标记。
网页区域与人工分类仍在既有来源表保存。OCR文字不会自动变成可信事实。
`image_plans` 保存平台图片区域、顺序、用途与1–5张原图引用。
原图是什么与最后放在哪里分别保存，同一原图可用于多个生成位置。

内容页先点击“查看 AI 图片规划”，查看模型决定的轮播、SKU与详情模块及缺口。
数量由模型根据证据决定，单次30张是资源保护上限。SKU只能使用数据库真实
SKU图片URL匹配的关联，不能按颜色/包装猜测。

“按规划生成并审核”使用 wan2.7-image-pro 多图生成，每轮由独立的视觉调用对照
原图检查颜色、印花、比例、结构、SKU、安装接触和用途。总共最多3次生成，
后两次会把上一轮成图作为待修改目标，并携带结构化审核包（问题、必改项和
不可改变项），因此是针对失败图的修复，不是重新随机生成。网络或返回结构异常
停止当前图片，允许人工重试。全部未通过则保存每一轮成图和审核记录，生成明确
修复方案，不将失败图作为成功成品下载或确认。

规划阶段优先为搜索首图选择无促销叠字、无遮挡、主体清楚的原图。若三轮失败由
参考素材污染或证据不足导致，页面的“按建议重新生成”会重新规划，并自动避开
上一轮问题来源图；若只是视觉质量问题，则保留规划位置继续修复。

生成前可由用户选择审核强度：无规则不调用AI视觉审核（仅校验文件与尺寸，1轮）；
轻度规则60分（最多2轮）；正常规则75分（最多2轮）；严谨规则90分（最多3轮）。
审核总分由商品一致性40分、事实合规25分、当前单图用途20分、视觉质量15分组成。
只有当前档位的阻断问题或总分不足才触发返工，普通警告和优化建议不阻止图片通过。
审核档位、阈值、分项分数与每轮结论随图片版本保存；人工确认门禁始终保留。

输出等比缩放留白，轮播按平台尺寸，SKU为800×800，详情第一版每个模块为
750×1500；不拉伸、不直接裁掉商品。内容页“一键生成完整图文”先让图片模型
生成无字底图，再按图片用途从当前已审核平台字段中选择短文案，由Pillow使用
中文字体确定性排版，随后审核整张成品。搜索首图默认无新增文字；轮播卖点图、
场景图和详情图可带对应文案，参数图只使用数据库已有参数。每条排版文案保存
source_field；事实ID只用于后端追溯，不直接印在图片上。参数/售后缺证据时仍
写入缺口，原图里的营销承诺不视为可靠事实。

可配置 `PINTAN_VISION_MODEL`（默认qwen3.7-plus）与 `PINTAN_EDIT_MODEL`
（默认wan2.7-image-pro）。尺寸参数图单独使用 `PINTAN_PARAMETER_MODEL`
（默认wan2.7-image-pro）：模型直接完成参数板、多视角、白名单文字和尺寸线，
审核负责拦截额外标语与错误尺寸；其他图仍采用无字底图加程序排版。
密钥仍由后端读取.env，不保存到任务记录。

测试：`python -m unittest tests.test_image_workflow tests.test_collector_bridge tests.test_media_pipeline tests.test_asset_repair -q`
在线验收：`python scripts/smoke_image_workflow.py --all --generate`。
在线脚本先用SQLite备份API备份数据库，处理当前垃圾袋全部有效素材，生成一个
规划位置，报告保存到outputs/image-workflow-smoke.json。
